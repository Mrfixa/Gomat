# GoMarket Architecture Documentation

## Overview

GoMarket is a production-grade, multi-vendor cryptocurrency marketplace supporting Monero (XMR) and Nano. The system follows a layered architecture pattern with clear separation of concerns.

**Stack:** Go 1.25, PostgreSQL, Chi Router, Templ (compile-time HTML), River (job queue)

## Key Components

### 1. Order Service (`internal/service/order/`)

**State Machine Transitions:**
```go
validTransition(current, next) bool
- Pending → Paid, Cancelled ✓
- Paid → Accepted, Declined ✓
- Accepted → Dispatched ✓
- Dispatched → Finalized, Disputed ✓
- Disputed → Settled ✓
```

**Key Functions:**
- `Create()` - Creates order from cart
- `Accept()` - Vendor accepts, updates inventory
- `Decline()` - Vendor declines, refunds customer
- `Dispatch()` - Vendor ships
- `Finalize()` - Buyer confirms, credits vendor
- `Dispute()` - Buyer opens dispute

### 2. Payment Service (`internal/service/payment/`)

**Invoice States:**
```
PENDING → CONFIRMED (when amount >= required)
       → EXPIRED (after 6 hours, non-permanent)
```

**Double-Spend Protection:**
- Logs warning if received > expected
- Still confirms if >= required amount
- Idempotent processing (skip if already confirmed)

### 3. Auth Service (`internal/service/auth/`)

**Constants:**
```go
MaxFailedLoginAttempts = 5
LockoutDuration = 15 * time.Minute
FailedAttemptWindow = 30 * time.Minute
MaxPasswordHistory = 5
TokenLength = 26
```

### 4. Jail (Anti-Bot) (`pkg/jail/`)

**CAPTCHA System:**
- Generates image with onion address
- Randomly hides 2-4 characters
- User must identify missing characters
- Configurable difficulty
